Computer Science & Engineering Computer Networks Project

DNS Query and Analysis Tool

A comprehensive Python Flask networking platform for DNS record resolution, latency benchmarking, database telemetry, Matplotlib visual analytics, and Wireshark packet capture dissection.

1. Introduction & Problem Statement
1.1 Introduction

The Domain Name System (DNS) is one of the most fundamental infrastructure pillars of the global Internet. It operates as the distributed, hierarchical directory translating human-memorable domain names (e.g., google.com) into machine-routable Internet Protocol addresses (IPv4 and IPv6). Understanding DNS behaviors, measuring server response latency, resolving multiple resource records, and inspecting lower-level network packets are core competencies in Computer Networks, Cybersecurity, and Cloud Systems.

1.2 Problem Statement

Command-line utilities such as nslookup, dig, and host provide basic DNS lookup capabilities, but they lack automated latency telemetry tracking, multi-domain comparative benchmarking, persistent historical aggregation, graphical analytics, and integrated packet capture dissection in a centralized, intuitive interface. Students and network administrators frequently need to toggle between terminal commands, database tools, and external packet sniffers. This project bridges that gap by creating an integrated web-based diagnostic suite built entirely in Python.

2. Project Objectives & Scope
Core Objectives
  • Standard Record Resolution: Resolve authoritative A (IPv4), AAAA (IPv6), CNAME (Aliases), and MX (Mail Exchange with priority) records using RFC-compliant dnspython.
  • High-Precision Telemetry: Measure query round-trip time (RTT) down to fractional milliseconds using Python's time.perf_counter().
  • Multi-Domain Benchmarking: Simultaneously evaluate up to 10 domains to calculate minimum, maximum, and average response times and identify relative performance bottlenecks.
  • Persistent Database Auditing: Log all queries, statuses (SUCCESS, NODATA, NXDOMAIN, TIMEOUT, ERROR), answers, and resolvers in an indexed SQLite database.
  • Server-Side Visual Analytics: Generate high-resolution statistical charts via Matplotlib directly on the Flask backend without JavaScript chart dependencies.
  • Packet Inspection: Parse and dissect binary Wireshark capture files (.pcap/.pcapng) to display lower-level IP headers, ports, transaction IDs, opcodes, and DNS flags.
Project Scope
  • Target Audience: Computer Science Engineering students, networking educators, systems administrators, and cybersecurity analysts.
  • Operational Environment: Runs cross-platform on Windows 10/11, macOS, and Linux in VS Code with Python 3.
  • Protocol Coverage: Standard authoritative and recursive DNS over UDP/TCP port 53.
  • Export Formats: Seamless data extraction via RFC-compliant CSV and structured JSON formats.
  • Zero Frontend Framework Dependencies: Built purely with HTML5, CSS3, and server-rendered Flask Jinja2 templates.
3. Technology Stack & Architecture
Component / Layer Technology Purpose in Project
Backend Language Python 3 Core execution engine, timing measurements, and business logic.
Web Framework Flask (WSGI) Routing, request dispatching, session handling, POST-Redirect-GET pattern.
Template Engine Jinja2 Server-side HTML rendering, template inheritance, dynamic UI updates.
DNS Query Engine dnspython Constructs raw DNS question packets, parses response RRsets, handles timeouts.
Database Store SQLite 3 Persistent transactional query history, indexing, metric aggregation.
Visualization Engine Matplotlib (Agg) Generates headless high-DPI latency charts, line graphs, and donut charts.
Packet Analyzer Scapy & Binary Streamer Inspects Wireshark PCAP/PCAPNG captures, decodes DNS header bits and RCODEs.
Frontend Presentation Bootstrap 5 + Custom CSS Responsive layout, cybersecurity navy/cyan theme, accessible cards and tables.
4. System Requirements
Hardware Requirements
  • Processor: Dual-Core Intel/AMD x86_64 or ARM64 processor (1.5 GHz or higher).
  • Memory (RAM): 2 GB minimum (4 GB recommended for large packet captures).
  • Storage: 250 MB free disk space for Python runtime, dependencies, and database.
  • Network Interface: Active Internet connection (Ethernet or Wi-Fi) with UDP port 53 outbound access.
Software Requirements
  • Operating System: Windows 10/11, macOS 12+, or Ubuntu/Debian Linux.
  • Development Environment: Visual Studio Code (VS Code) with Python extension.
  • Runtime: Python 3.9 through Python 3.15.
  • Web Browser: Any modern standards-compliant browser (Chrome, Edge, Firefox, Safari).
  • Optional: Wireshark Desktop GUI for capturing live network packets.
5. Advantages & Limitations
Key Advantages
  • Zero JavaScript Framework Overhead: Fast page loads, maximum security, and full accessibility without heavy single-page application frameworks.
  • Accurate Real-World Telemetry: All statistics come from actual socket queries; no simulated or fake numbers.
  • Safe POST-Redirect-GET Pattern: Prevents duplicate query triggers when users refresh result pages.
  • Portable & Self-Contained: SQLite database is zero-configuration and runs directly from local workspace files.
  • Embedded Demo Generator: Out-of-the-box sample PCAP generator allows immediate testing even without Wireshark installed.
Technical Limitations
  • Encrypted DNS Invisibility: Standard packet capture cannot inspect DNS-over-HTTPS (DoH) or DNS-over-TLS (DoT) payloads without private session key extraction.
  • Local Network Firewall Filtering: Corporate firewalls or captive portals that intercept port 53 may influence recorded response latency.
  • Query Rate Limits: Public nameservers (such as Google 8.8.8.8) enforce rate limiting against rapid automated query bursts.
  • In-Memory Capture Processing: Very large packet captures (>50 MB) require significant RAM for dissection.
6. Future Enhancements & Conclusion
6.1 Future Enhancements
DNSSEC Validation: Verification of cryptographic RRSIG and DNSKEY signatures for anti-tamper validation.
Geo-IP Mapping: Integration with MaxMind GeoLite2 to display geographic locations of resolved IP endpoints.
DoH / DoT Clients: Built-in resolution capabilities over encrypted HTTPS and TLS channels.
6.2 Conclusion

The DNS Query and Analysis Tool successfully demonstrates the practical implementation of core networking concepts in Python. By uniting domain resolution, latency telemetry, comparative benchmarking, persistent relational storage, automated Matplotlib chart generation, and packet dissection into a cohesive web dashboard, this project serves as an ideal capstone deliverable for Computer Science Engineering students and instructors.
